# V1.0 — Operação local (release candidate)

Este guia descreve a candidata V1.0 para **Windows 11 x64**, uso individual e
loopback. A candidata ainda não foi promovida nem distribuída em uma tag ou
GitHub Release. Para executar este procedimento, use o checkout candidato
fornecido pelo responsável; não obtenha V1.0 pela tag antiga `v0.5.0`.

Identidades: produto `V1.0`; pacote/aplicação `1.0.0`; portabilidade
`CEI-EXPORT-1.0`, `format_version = 1.0`. A versão do produto aparece no
rodapé da interface. Esses valores não são intercambiáveis.

## Instalação limpa

Pré-requisitos: Windows 11 x64, PowerShell 5.1 ou posterior, Git, internet na
primeira sincronização e `uv 0.12.7`. Não instale Python ou dependências por
`pip`; o lock fixa CPython `3.13.15`.

1. Obtenha o snapshot/checkout candidato fornecido pelo responsável em uma
   pasta nova. V1.0 ainda não tem distribuição pública. Não use um checkout com
   alterações locais fora da lista aprovada. Confirme que a raiz contém
   `pyproject.toml`, `uv.lock`, `.python-version` e `manage.py`.
2. Confira Git e `uv`:

   ```powershell
   git --version
   uv --version
   ```

   Se a fonte tiver metadados Git (`.git`), confira também
   `git status --short` e compare a saída à lista aprovada que acompanha o
   candidato. Um snapshot sem `.git` não fornece histórico/status de Git.

   A versão esperada de `uv` é `0.12.7`. Se faltar, use o instalador oficial
   fixado. Para manter a ferramenta isolada neste checkout e não alterar o PATH
   permanente, prepare diretórios locais no PowerShell atual:

   ```powershell
   $env:UV_INSTALL_DIR = Join-Path $PWD ".tools\uv"
   $env:UV_NO_MODIFY_PATH = "1"
   $env:UV_CACHE_DIR = Join-Path $PWD ".tools\cache"
   $env:UV_PYTHON_INSTALL_DIR = Join-Path $PWD ".tools\python"
   powershell -ExecutionPolicy Bypass -Command "irm https://astral.sh/uv/0.12.7/install.ps1 | iex"
   $env:PATH = "$env:UV_INSTALL_DIR;$env:PATH"
   uv --version
   ```

   A saída esperada é `uv 0.12.7`. Esses diretórios de ferramenta/cache/runtime
   são locais e descartáveis; não os adicione ao Git.

3. Na raiz do checkout, sincronize sem modificar o lock:

   ```powershell
   uv sync --locked
   ```

   Se falhar, preserve a mensagem e pare. Não use `uv lock`, `pip install` ou
   um Python global para contornar a falha.
4. Crie o banco vazio e aplique apenas as migrations existentes:

   ```powershell
   New-Item -ItemType Directory -Force var
   .\.venv\Scripts\python.exe manage.py migrate
   ```

   Para primeiro uso pela interface, não execute `bootstrap_local`: sem
   Workspace, a página inicial encaminha para `/primeiro-acesso/`.
5. Inicie pelo entry point suportado:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-local.ps1
   ```

   O script usa `127.0.0.1:8000`, não migra nem inicializa o banco, não abre o
   navegador e encerra no mesmo terminal com `Ctrl+C`. Para outra porta,
   passe `-Port 8001`.
6. Abra <http://127.0.0.1:8000/>. No primeiro acesso escolha o fuso IANA e
   conclua a configuração do Workspace. Confira a página inicial e o rodapé
   `Versão V1.0`. Verifique health:

   ```powershell
   Invoke-RestMethod http://127.0.0.1:8000/health/
   ```

   O esperado é HTTP `200` e estado `healthy`. A aplicação deve permanecer
   vinculada a loopback; não use `0.0.0.0`. Encerre com `Ctrl+C`.

## Primeiro uso

O formulário inicial pede um fuso IANA explicitamente; a aplicação não infere o
fuso do computador. Após confirmar, verifique a página Início/dashboard e
Configurações. Não importe CEI nem restaure backup para inicializar uma
instalação nova. Se preferir preparar um Workspace via terminal, o comando
idempotente é:

```powershell
.\.venv\Scripts\python.exe manage.py bootstrap_local --timezone America/Sao_Paulo
```

Use o fuso escolhido pelo operador, não necessariamente o exemplo acima.

## Atualização local

Não há atualizador automático nem downgrade automático. A candidata V1.0 ainda
não tem tag/release publicada; portanto, não aplique este fluxo ao banco de uso
real até receber uma revisão candidata identificada e autorizada. O ensaio S7
usa somente cópias sintéticas isoladas.

1. Leia as notas da revisão de destino e confirme a identidade do produto,
   requisitos, migrations já existentes e compatibilidade da origem.
2. Pare a aplicação com `Ctrl+C`. Se a instalação tiver metadados `.git`, rode
   `git status --short` e resolva alterações locais antes de continuar; não use
   `git reset --hard` ou `git pull` para descartá-las. Um bundle/snapshot sem
   `.git` não pode informar status: registre sua versão/revisão e compare a
   identidade do destino com as notas fornecidas.
3. Confirme o perfil e o banco configurados. Crie e valide um pré-backup com
   nome novo, conforme [Backup e restore](#backup-e-restore).
4. Obtenha o bundle ZIP exato do candidato por canal autorizado, junto com sua
   versão de produto/revisão e SHA-256 esperado. Não existe tag ou bundle público
   V1.0 enquanto a candidata não for publicada. Na pasta da instalação antiga,
   informe o caminho e o digest recebidos, valide-os e extraia em diretório novo:

   ```powershell
   $oldInstallRoot = (Get-Location).Path
   $candidateBundle = Read-Host "Caminho do bundle candidato recebido"
   $expectedSha256 = (Read-Host "SHA-256 fornecido pelo responsável").Trim()
   $actualSha256 = (Get-FileHash -LiteralPath $candidateBundle -Algorithm SHA256).Hash
   if ($actualSha256 -ne $expectedSha256) { throw "Digest do candidato divergente; pare." }
   $candidateSuffix = Get-Date -Format "yyyyMMdd-HHmmss"
   $candidateRoot = Join-Path (Split-Path $oldInstallRoot -Parent) "candidate-v1-$candidateSuffix"
   if (Test-Path -LiteralPath $candidateRoot) { throw "A pasta candidata já existe; escolha uma pasta nova." }
   Expand-Archive -LiteralPath $candidateBundle -DestinationPath $candidateRoot
   foreach ($name in @("pyproject.toml", "uv.lock", ".python-version", "manage.py")) {
       if (-not (Test-Path -LiteralPath (Join-Path $candidateRoot $name) -PathType Leaf)) {
           throw "Bundle inválido: falta $name na raiz extraída."
       }
   }
   ```

   A raiz do ZIP recebido deve conter diretamente os quatro arquivos conferidos.
   Se identidade/digest divergir ou a extração não tiver essa estrutura, pare.
   Preserve intactos a pasta antiga, seu banco, backup e configuração.
5. Ainda na pasta antiga e no mesmo PowerShell, converta o caminho do banco
   efetivo em absoluto antes de mudar de pasta. Selecione o perfil preparado;
   para development, usa o banco configurado se existir ou o padrão abaixo:

   ```powershell
   $profile = Read-Host "Perfil da instalação: development ou production_local"
   if ($profile -notin @("development", "production_local")) { throw "Perfil inválido; pare." }
   if ($profile -eq "development") {
       $databasePath = if ([string]::IsNullOrWhiteSpace($env:CEI_DEVELOPMENT_DB)) {
           ".\var\development.sqlite3"
       } else {
           $env:CEI_DEVELOPMENT_DB
       }
       $env:CEI_DEVELOPMENT_DB = (Resolve-Path -LiteralPath $databasePath).Path
       if (-not (Test-Path -LiteralPath $env:CEI_DEVELOPMENT_DB)) { throw "Banco development ausente; pare." }
   } else {
       $productionDatabase = if ([string]::IsNullOrWhiteSpace($env:CEI_PRODUCTION_LOCAL_DB)) {
           ".\var\production_local.sqlite3"
       } else {
           $env:CEI_PRODUCTION_LOCAL_DB
       }
       $env:CEI_PRODUCTION_LOCAL_DB = (Resolve-Path -LiteralPath $productionDatabase).Path
       if (-not (Test-Path -LiteralPath $env:CEI_PRODUCTION_LOCAL_DB)) { throw "Banco production_local ausente; pare." }
       if ([string]::IsNullOrWhiteSpace($env:CEI_SECRET_KEY)) { throw "CEI_SECRET_KEY ausente; pare sem exibi-la." }
   }
   ```

   Mantenha esse mesmo PowerShell aberto e use-o também nos comandos a seguir;
   a variável do banco selecionado fica absoluta antes de mudar de pasta. Nunca
   copie ou imprima `CEI_SECRET_KEY`. Se o perfil/banco efetivo não for
   conhecido, pare.
6. Ainda no mesmo PowerShell, mantenha tool/cache/runtime dentro da instalação
   antiga, como no passo 2. Use o `uv` local que já existe ou instale a versão
   fixada se ele estiver ausente; então entre na raiz extraída e sincronize:

   ```powershell
   $env:UV_INSTALL_DIR = Join-Path $oldInstallRoot ".tools\uv"
   $env:UV_NO_MODIFY_PATH = "1"
   $env:UV_CACHE_DIR = Join-Path $oldInstallRoot ".tools\cache"
   $env:UV_PYTHON_INSTALL_DIR = Join-Path $oldInstallRoot ".tools\python"
   if (-not (Test-Path -LiteralPath (Join-Path $env:UV_INSTALL_DIR "uv.exe"))) {
       powershell -ExecutionPolicy Bypass -Command "irm https://astral.sh/uv/0.12.7/install.ps1 | iex"
   }
   $env:PATH = "$env:UV_INSTALL_DIR;$env:PATH"
   uv --version
   Set-Location -LiteralPath $candidateRoot
   uv sync --locked
   .\.venv\Scripts\python.exe --version
   ```

   Exija `uv --version` = `0.12.7` e Python `3.13.15`. `uv sync --locked` deve
   sair com `0`; o `uv.lock` do candidato deve permanecer byte-a-byte igual ao
   bundle recebido (a versão antiga pode ter outro lock). Não use `uv lock` ou
   `pip install`.
7. Confira migrations e aplique somente as já declaradas na revisão, no banco
   selecionado explicitamente acima:

   ```powershell
   .\.venv\Scripts\python.exe manage.py showmigrations
   .\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
   .\.venv\Scripts\python.exe manage.py migrate
   .\.venv\Scripts\python.exe manage.py showmigrations
   ```

   A saída esperada de `makemigrations --check --dry-run` é `No changes
   detected`. Não use `makemigrations` para criar migrations durante uma
   atualização. Compare IDs/contagens e estado esperado com a linha de base
   registrada antes do update; diferença sem explicação é parada.

   Esses comandos de exemplo usam o perfil `development`. Se a instalação usa
   `production_local`, acrescente `--settings=config.settings.production_local`
   a cada comando `manage.py` e inicie com
   `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-local.ps1 -Profile production_local`;
   mantenha `CEI_PRODUCTION_LOCAL_DB` e `CEI_SECRET_KEY` apenas no ambiente
   local, sem copiar nem imprimir o segredo.
8. Rode checker, inicie o servidor pela pasta do bundle e confira health antes
   de retomar o uso:

   ```powershell
   .\.venv\Scripts\python.exe manage.py check_integrity
   powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-local.ps1
   ```

   Checker: exit `0` saudável; `2` findings; `3` falha operacional inconclusiva.
   Em `2` ou `3`, pare e preserve banco, backup e logs. Após health `200`, faça
     smoke da página Início e de Dados, confirme IDs/contagens, histórico e
     estado de revisão/policies esperados, e registre a revisão/digest usados.
   Não trate restore isolado como downgrade.

## Checker de integridade

Com a aplicação parada ou em execução local, rode na raiz:

```powershell
.\.venv\Scripts\python.exe manage.py check_integrity
```

É somente leitura e não corrige dados. Exit `0` significa sem finding no
catálogo verificado; `2` significa finding; `3` significa que a verificação não
concluiu operacionalmente. Preserve os logs sanitizados e não continue uma
operação relevante com `2` ou `3`.

## Backup e restore

Mantenha o perfil/banco em uso conhecido. No exemplo development, o padrão é
`var/development.sqlite3`; `CEI_DEVELOPMENT_DB` pode selecionar outro caminho.
Não copie arquivos `.env`, chaves ou bancos para compartilhar evidência.

Crie pastas e nomes novos e faça o backup antes de atualização ou recovery:

```powershell
New-Item -ItemType Directory -Force backups
New-Item -ItemType Directory -Force recovery
.\.venv\Scripts\python.exe manage.py check_integrity
.\.venv\Scripts\python.exe manage.py backup_sqlite --output .\backups\v1-pre-operation.sqlite3
.\.venv\Scripts\python.exe manage.py validate_backup --backup .\backups\v1-pre-operation.sqlite3
```

Exit `0` em backup/validação confirma a criação/validação física do par
SQLite + `.manifest.json`; mantenha os dois arquivos juntos e protegidos.
SHA-256 detecta alteração, mas não autentica a origem e não prova sozinho que
um restore abrirá a aplicação.

Para provar recuperação sem tocar no banco em uso, restaure sempre em arquivo
novo e isolado:

```powershell
.\.venv\Scripts\python.exe manage.py restore_backup --backup .\backups\v1-pre-operation.sqlite3 --destination .\recovery\v1-verified.sqlite3
```

O destino precisa não existir. Exit `0` valida SQLite, reconciliação e checker
S5 na cópia; `2` indica findings e `3` falha operacional. Isso **não** adota a
cópia como banco ativo. Preserve origem, backup, sidecar e destino se falhar.

## Recovery offline de backup preparado na interface

Use somente para um ticket criado e validado pela tela Dados em instalação
isolada. Nunca execute contra banco ativo de outra instalação.

1. Confirme o perfil e banco-alvo e faça/valide um pré-backup com nome novo.
2. Na tela Dados, selecione os arquivos SQLite e manifesto correspondentes,
   execute a validação/prévia e confira o impacto. Para confirmar, selecione o
   mesmo par, confirme explicitamente a ação e digite `RESTAURAR`. Guarde o
   ticket apresentado; o banco ativo ainda não foi trocado.
3. Encerre o servidor com `Ctrl+C` e confirme que ele está parado. Não prossiga
   se o processo ou o caminho do banco não estiver claro.
4. Na raiz e com o mesmo ambiente/configuração do perfil que preparou o ticket,
   execute o comando exibido pela tela:

   ```powershell
   .\.venv\Scripts\python.exe manage.py apply_prepared_restore --ticket <ticket> --settings=config.settings.development
   ```

   Use `config.settings.production_local` se esse foi o perfil preparado. O
   comando é offline e usa o candidato e pré-backup validados pelo ticket. Não
   redirecione o alvo para outro banco.
5. Prossiga somente se a saída JSON indicar `status: RESTORED`. Reinicie com
   `scripts/start-local.ps1`, confirme health, confira o estado esperado e rode
   `check_integrity`. Mantenha o pré-backup até concluir a reconciliação.

Se o ticket, perfil, estado do servidor ou destino divergir, pare sem aplicar.
Falha ou saída diferente de `RESTORED` não é PASS; preserve ticket e artefatos
para diagnóstico. Nunca restaure sobre arquivo ativo por cópia manual.

## CEI

CEI é portabilidade funcional ZIP/JSON, não cópia SQLite. Importa somente em
instalação compatível, migrada e sem Workspace. V1 reconhece produtores `V0.5`
e `V1.0` sob validação estrita. Não há merge, conversão, coerção, importação
parcial, remapeamento, adaptação de schema ou repair. Veja o
[contrato CEI](CEI_EXPORT_1_0.md).

## Solução de problemas

- `uv` ausente: instale `0.12.7` pelo passo fixado deste guia e reabra o shell.
- versão de `uv` divergente ou lock inconsistente: obtenha novamente a revisão
  candidata correta; não rode `uv lock` nem `pip install`.
- `.venv` ausente/Python incorreto: na raiz do checkout execute `uv sync --locked`.
- porta `8000` ocupada: identifique conscientemente o processo ou escolha uma
  porta loopback livre com `-Port`; não mate processos automaticamente.
- banco/perfil inesperado: confira `CEI_DEVELOPMENT_DB` ou
  `CEI_PRODUCTION_LOCAL_DB`; pare antes de qualquer escrita.
- backup inválido ou checksum divergente: preserve o par e gere outro backup
  a partir de origem saudável; não edite manifesto para forçar validação.
- checker exit `2`/`3`: não continue operação de dados; preserve cópias e
  evidência sanitizada.
- restore recusado: verifique par, compatibilidade e destino novo; não tente
  substituir banco ativo.
- recovery sem ticket/servidor parado: não execute `apply_prepared_restore`.
- CEI inválido: exporte novamente de produtor compatível e destino vazio; não
  modifique ZIP ou schema para fazê-lo passar.

## Limites e suporte

Windows 11 x64; individual/local/loopback. Sem autenticação remota, hospedagem
pública, API pública, mobile oficialmente suportado, instalação nativa, serviço
residente, update automático, downgrade automático, agenda/rotação de backup ou
armazenamento em nuvem. O checker cobre regras documentadas, não todos os
defeitos possíveis. A matriz oficial de browser é a do
[adendo S4](V1.0_Adendo_V10-D2_Matriz_de_Browsers_S4.md).

O suporte V1 é documental, sem SLA, atendimento 24/7, prazo garantido,
compromisso comercial ou manutenção contratual. A página pública do projeto
oferece Issues para registro de defeitos; não há promessa de resposta ou prazo.
